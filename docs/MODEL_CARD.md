# Model card: aarav-lm `small` (14M)

A small decoder-only language model written and trained from scratch (no pretrained weights, no borrowed model code) on one
MacBook Air M3 with 8 GB. It writes short, simple children's stories, and a fine-tuned variant follows a few kinds of story request.
It is a research and portfolio artefact, **not a general assistant**.

## Which checkpoint

| | What | Where it comes from |
|---|---|---|
| **exp_013** (default in the demo site) | the longer-pretrained base (exp_010) + about two epochs of supervised fine-tuning on rule-checkable story requests, training seed 1338 | `experiments/exp_013_sft_small_instruct_v6_long_2ep_seed1338/` |
| exp_012, exp_014 | the same recipe with seeds 1337 and 1339; scores differ from exp_013 by up to 7.6 points on unseen wording | `experiments/exp_012_*`, `exp_014_*` |

| exp_011 | the exp_012 recipe with one epoch (loses length control) | `experiments/exp_011_sft_small_instruct_v6_long/` |
| exp_004 / exp_010 | the pretrained bases (no fine-tuning) | `experiments/exp_004_*`, `exp_010_*` |
| tiny (5M) | earlier, smaller model, packaged as int8 in `models/` | `models/README.md` |

Weights are not committed (`experiments/*/checkpoints/` is git-ignored); the configs, logs, metrics and evaluation records are, and
every number below can be regenerated from them ([RESULTS.md](RESULTS.md)).

## Architecture

Llama-style decoder-only transformer: RoPE positions, RMSNorm, SwiGLU feed-forward, grouped-query attention (6 query heads sharing 2
key/value heads), tied input and output embeddings, KV cache for decoding.

| | |
|---|---|
| Parameters | 14,162,304 (12,589,440 outside the embedding table) |
| Layers, width | 8, 384 |
| Attention | 6 query heads, 2 KV heads, head size 64 |
| Feed-forward | SwiGLU, hidden size 1,024 |
| Context | 512 tokens |
| Vocabulary | 4,096 (byte-level BPE trained on the training split only) |
| Size on disk | 54 MB fp32 (an int8 export is about 4× smaller, [PERFORMANCE.md](PERFORMANCE.md)) |

## Training data

* **Pretraining:** TinyStories V2 (GPT-4-written short stories, CDLA-Sharing-1.0), see [DATASETS.md](DATASETS.md). Split into train,
  validation and test by a hash of the story's content, so a story never appears in two splits and the assignment does not change when
  more data is added. The tokenizer saw only the training split. exp_004 saw 90M tokens; exp_010 continued for 147M more.
* **Fine-tuning:** synthetic story requests ("write a story about a dragon, at most 90 words") paired with real stories that satisfy
  each request by rule, generated by `scripts/make_instruct_data.py` from the training split only. Loss is computed on the assistant
  reply only. The data are described, with their known defects, in [RESULTS.md](RESULTS.md) and [CORRECTNESS.md](CORRECTNESS.md).

Because both the stories and the requests are machine-made, the model's language is the language of TinyStories: simple sentences, a
small vocabulary, a small set of characters and morals. No personal data was collected or used.

## Training procedure

AdamW (β 0.9/0.95), linear warm-up then cosine decay, gradient clipping at 1.0, fp32 on the Apple GPU (MPS), batch of 32 sequences
via gradient accumulation, deterministic seed, atomic checkpoints, bit-exact resume. Pretraining exp_004: 5,500 steps, 90.1M tokens,
4.09 h. exp_010: 9,000 steps, 147.5M tokens, 7.7 h. Fine-tuning: 1,800 steps (about one epoch) for exp_009 and exp_011, 3,600 (about two) for exp_012. Details and the health checks that ran
alongside (loss-spike and gradient monitors) are in [TRAINING.md](TRAINING.md).

## Evaluation

Language modelling, scored on **every** window of the held-out splits, with a bootstrap standard error (validation split of the 1200 MB corpus,
2,927 windows):

| | val loss | perplexity | top-1 next token | bits per byte |
|---|---|---|---|---|
| exp_004 | 1.4036 ± 0.0038 | 4.07 | 63.5% | 0.512 |
| exp_010 | **1.2876 ± 0.0037** | **3.62** | 65.6% | 0.470 |

Following requests, scored by rules on held-out stories, with chance level (a story that ignores the request passes 10.5% of the
time), intervals over distinct prompts, and a **final evaluation set written and committed before any model was scored**:

| pass rate (greedy) | untuned base | exp_009 | exp_011 | exp_012 (seed 1337) | **exp_013 (seed 1338)** | exp_014 (seed 1339) |
|---|---|---|---|---|---|---|
| never-seen wording (final set) | 39.9% | 46.5% | 44.4% | 45.1% | **52.1%** | 52.8% |
| training-style wording | 41.7% | 64.2% | 55.9% | 61.1% | **74.3%** | 65.3% |
| development set | 40.6% | 50.3% | 44.1% | 49.0% | **57.3%** | 55.2% |

Sampled decoding (how the chat samples), never-seen wording: untuned 34.7%; exp_009 41.7%; exp_011 41.7%; the three seeds 44.1%, **50.3%**, 44.1%.

**How much to trust these numbers.** The last three columns are one recipe trained three times, nothing changed but the random seed: the score on unseen wording varies by
7.6 points (standard deviation 4.2), and which length skill appears varies too (`long` 79 / 17 / 21%, `short` 25 / 88 / 0%). Every other version was trained once, so differences of a few points between
versions cannot be told apart from luck; the confidence intervals in the evaluation dashboard cover the prompts asked, not this retraining spread. What holds in every run: the fine-tuned models beat the untuned base
(three-seed mean 50.0% vs 39.9% greedy, 46.2% vs 34.7% sampled). exp_013 was chosen for the demo site by the mean of the development and trained-wording sets, before looking further; its best-of-three score on the final
set is partly luck and will regress toward the mean. Topic, emotion and named-character requests are followed reasonably in every run (topic 88 to 92%); **length requests and requests for two topics are unreliable**.

## Intended use

* Learning, demonstration and study of a complete from-scratch pipeline: data, tokenizer, training, evaluation, serving.
* Generating simple children's-story text on a laptop or a small server (about 370 tokens/s on the M3's CPU).

## Out of scope and known limitations

* **Not a general assistant.** It has no world knowledge beyond what stories contain and cannot reason, answer questions, summarise,
  translate, write code or do arithmetic.
* Story logic drifts, names and pronouns sometimes disagree, and greedy decoding can loop; requests are followed about as often as
  the numbers above say, which is less than half the time on new wording.
* **Not audited for bias, toxicity or safety.** The training text was generated by another model and was not filtered by this
  project beyond de-duplication and length; the model has no refusal or moderation behaviour. It should not be used for anything
  where such output would matter, and a public deployment should keep the "small story model" notice the site already shows.
* English only.
* Evaluation covers a narrow set of rule-checkable request kinds; it says nothing about story quality as a person would judge it, which was
  not measured.
